Restored an independent default of 80 for the stateless-svc Service port, so in-cluster URLs without a port keep working whatever port a container listens on.

- `stateless-svc/templates/service.yaml`, `stateless-svc/templates/httproute.yaml`: the Service port and the HTTPRoute backend port both read `service.port`, with no fallback to `container.port`; the Service still reaches the container by port name
- `stateless-svc/values.yaml`: `service.port` defaults to 80
- `stateless-svc/Chart.yaml`: version 1.6.3, a patch, since this restores the 1.5.x default and few deployments run 1.6.0 to 1.6.2
- `stateless-svc/MIGRATION.md`: 1.6.2 to 1.6.3 entry with the two remedies for deployments that named the container port in their URLs, and a pointer from the 1.6.0 entry it supersedes
- `stateless-svc/tests/serviceport_test.yaml`: tests for the default and an explicit Service port, the container port and probes staying on the container port, and the route backend following the Service port
