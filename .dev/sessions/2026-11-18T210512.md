stateless-svc 1.7.0: chosen keys of a secret, files from values as ConfigMaps, and a fix for created Secrets, so Usher's Controller can mount its database's CA certificate without the private key stored beside it.

- `stateless-svc/templates/_volumes.tpl`: `mountSecrets[].secret.items` mounts chosen keys of a secret, since CNPG keeps a cluster's CA certificate and its private key in one secret; the mount stays a directory, so a reissued certificate reaches the running pod
- `stateless-svc/templates/configmaps.yaml`, `stateless-svc/templates/_configmaps.tpl`, `stateless-svc/templates/deployment.yaml`: `configMaps` entries each name a ConfigMap, the directory its files are mounted at and the files, chosen over mirroring `createSecrets` and `mountSecrets` so that one entry says where its files go; the restart hash covers ConfigMaps only, since a hash of secret values in the pod spec would let anyone who can read pods guess a weak secret
- `stateless-svc/templates/secrets.yaml`: two or more `createSecrets` entries render one Secret each; before, they rendered one manifest that failed to parse, so no release can have relied on it
- `stateless-svc/tests/configmaps_test.yaml`, `stateless-svc/tests/secrets_test.yaml`, `stateless-svc/tests/volumes_test.yaml`: tests for all three, written before the templates
- `stateless-svc/MIGRATION.md`, `stateless-svc/values.yaml`, `stateless-svc/Chart.yaml`: the 1.6.3 to 1.7.0 section, the new fields documented, version 1.7.0
